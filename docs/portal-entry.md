# Secure portal entry (#82)

The independently deployed portal uses Supabase Auth single-use email tokens.
Task URLs are plain /?task=<uuid> links, never bearer credentials. Signed-out
visitors explicitly request a fresh login link. No session/token is copied from
the management origin. Existing-password login remains available.

## Required hosted configuration

- VITE_MEMBER_PORTAL_URL in both builds must be the exact HTTPS portal origin.
- Supabase Auth redirect allowlist must permit only that origin's /auth/confirm
  path and its next query. Do not allow arbitrary domains or preview wildcards.
- Set Auth email OTP expiry to 600 seconds and request interval to at least 60
  seconds. Enable provider rate limits and production SMTP. These settings were
  not changed by this PR. Configure CAPTCHA before public registration at scale.
- Magic Link and Confirm Signup email templates must use this fragment link:

```html
<a href="{{ .RedirectTo }}#token_hash={{ .TokenHash }}&amp;type=email">Panelime giriş yap</a>
```

RedirectTo is generated by portalAuthRedirect and allowlisted by Auth.
The fragment keeps the temporary token out of HTTP request URLs. The page
removes it from browser history and consumes it only after a deliberate click,
not on an email-scanner GET. Invalid/expired/used links show a fresh-login action.
detectSessionInUrl:false prevents implicit token sessions; verifyOtp handles the
explicit token_hash exchange. Only email confirmation type is accepted.

Return destinations are root, a task/ticket UUID selector or a public registration
slug. Ownership remains enforced by the database, never by the link.

## Mail adapter boundary (#26/#85)

portalMessageLink returns no link for internal_welcome. Assignment/reminder links
select a task. Attendee confirmations select a ticket. No permanent auth token
is stored in a mail payload. Delivery integration is separate. No real emails,
worker changes, production SQL or hosted Auth settings were performed.

Staging gate #86: actual link request/consume/reuse/expiry, different device,
separate app origins, invalid next, original task destination and Auth rate limits.
Reference: https://supabase.com/docs/guides/auth/auth-email-passwordless
